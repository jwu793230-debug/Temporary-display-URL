第一遍：零基础讲解

第三集：AI 时代的软件怎样变化

开场：软件正在多出一种写法

过去，人把每条规则写成代码：如果温度高于某数值就报警。后来，人更多地准备数据，让神经网络自己从例子里学出识别规则。现在，大语言模型又让普通人可以用自然语言描述一部分程序行为。三种方式没有谁彻底取代谁；聪明的系统会把它们放在各自擅长的位置。

今天的路线图

理解 Software 1.0、2.0、3.0；理解为什么模型产品要保留人工接管；以及未来数字系统为什么要同时服务人和 Agent。

一、三种软件

Software 1.0 是传统代码，规则由工程师写清楚。它适合转账、权限、税率和任何必须稳定、可审计的事情。Software 2.0 是神经网络权重：你不直接写“怎样识别猫”，而是给足够多猫和非猫的图片，让训练过程形成内部参数。它适合视觉、语音、推荐这类很难穷举规则的任务。Software 3.0 指用提示词、上下文、范例、工具和评测来引导 LLM。它适合解释、归纳、草拟、在模糊语言中找线索。

二、自然语言编程的机会和边界

自然语言降低了表达需求的门槛。不会写代码的人也能描述“把这份会议记录变成待办清单，再按负责人分组”。但自然语言也天然有歧义：所谓“尽快”“重要”“合适”需要人定义。因此提示词不是按钮，而像一份不断完善的需求说明书。

三、部分自治比全自动更实用

成熟产品不必一开始就让 AI 独立完成一切。更好的方式是自治滑杆：低风险的分类、草稿、信息抽取可以自动做；发款、签约、删除数据、对外承诺等高风险动作必须展示理由并等待确认。人负责目标和最后责任，模型负责把中间的大量重复工作变快。

场景：客服和报销

客服系统可先读邮件、提取订单号、找出知识库答案、写一版回复，涉及退款或投诉升级时交给员工。报销系统可识别票据并建议分类，但金额异常、重复票据和政策例外应进入人工队列。这样既能提速，也能留下可审计轨迹。

四、为 Agent 重修数字道路

过去很多系统只为人类点按钮而设计。Agent 需要更清晰的 API、稳定字段、可读说明、细粒度权限、操作日志和可撤销步骤。网页界面不会消失，但未来优秀系统会让人、传统程序和 AI 都能安全协作。

误区与复盘

误区是把“能演示”当成“可无人值守”。真正难的是异常、权限、责任和恢复。带走三点：传统代码保底线，模型处理模糊信息，人始终能看见、纠正和接管关键流程。

第二遍：技术与应用补充

3. Karpathy：AI 时代的软件（39:32）

来源：B 站 BV1CLNtzyEP4；原讲为 YC AI Startup School 的 Software Is Changing (Again)。

核心论点：软件正在从“人写规则”到“训练权重”，再到“用自然语言编程 LLM”的第三次表达方式迁移；但 1.0/2.0/3.0 将长期并存。

  • Software 1.0：C++、Python、SQL 等显式规则；稳定、精确、可审计。
  • Software 2.0：训练数据和优化器“写出”神经网络权重；适合感知和难以手工写规则的模式。
  • Software 3.0：提示词、上下文、工具与评测共同“编程”LLM；自然语言成为接口，迭代速度更快。
  • LLM 既像按量调用的公共设施，也像集中制造的“fab”，还像有记忆、权限、工具和多任务的“新 OS”。这些类比提醒我们：今天仍非常早期。
  • 产品策略不是追求全自动：优先做“部分自治”。人设定目标、看到过程、能中断/接管；机器承担起草、检索、分类、执行低风险步骤。
  • 数字世界需要面向 Agent 重构：给机器可读文档、稳定 API、身份/权限、可观察状态和可验证操作，而非只给人类 GUI。
