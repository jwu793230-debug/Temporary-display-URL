AI 视频精讲：零基础课程教材

本教材按知识依赖重新整理六部英文视频的关键主题：模型怎样工作、怎样使用、怎样做成产品、怎样做工程，以及 Agent、AGI 与研究趋势。它是原创中文学习材料，不是逐字字幕或原视频替代品。

如何使用这本教材

先听每章音频，再读本章内容。第一次阅读抓住比喻和结论；第二次再看技术词和流程图。每一章都回答四个问题：它是什么、为什么重要、在现实中怎样使用、最容易在哪儿出错。

课程总览：能力不是魔法，可靠性来自完整系统

人的目标与材料 → LLM 的语言能力 → 检索与工具 → 验证、权限与人工接管 → 可靠交付

第一集：如何把 LLM 用在生活和工作中

开场：它不是万能答案机

把大语言模型想成一位见多识广、反应很快的实习生：它读过许多文字，能迅速写出初稿、换一种说法、列出方案，也愿意根据反馈修改。但它没有亲自经历过你公司的情况，不会天然知道你手里那份表格是否最新，更不会因为说得笃定就一定正确。学会用它，重点不是找一句神奇咒语，而是学会把工作交给它、检查它、再让它修改。

今天的路线图

我们要解决五个问题：什么事情适合交给模型；怎样把模糊想法说清楚；怎样让它使用资料和工具；哪些答案必须核验；以及怎样把一次聊天变成可靠的工作流程。

一、先把问题说清楚

人对人说“帮我写个方案”，对方通常会追问用途、读者、预算和截止日期。模型也一样。一个好任务至少有五个零件：目标、背景、输入材料、限制条件和交付格式。比如不要只说“帮我写邮件”，而说“给合作过一次的客户写一封 200 字以内的续约提醒；语气友好但不催促；说明价格不变；最后给出两个可选会议时间”。这不是让模型变聪明，而是减少它猜错方向的空间。

二、把模型当成协作者

最实用的做法是分轮工作。第一轮请它复述任务和列出缺失信息；第二轮请它给三个不同风格的提纲；第三轮挑一个方向展开；第四轮让它自己按清单审稿。这样你不是被动接受一大段文字，而是在驾驶。让它先给“计划”再做“正文”，常能明显减少跑题。

三、工具、核验与反复修改

模型擅长根据已见文字续写，不等于它随时掌握现实世界。价格、法规、新闻、合同条款、病情和财务数字，都应回到可靠来源核对。需要计算时用计算器或代码；需要公司资料时让它检索受控知识库；需要发邮件、改表格、提交订单时设置权限和人工确认。模型负责提出候选答案，工具负责取数和执行，人负责批准重要动作。

四、两个日常场景

场景一，孩子要做“垃圾分类”的小报告。你可以给模型年龄、时长和家里已有材料，让它设计提纲、解释词语、出三道练习题；但统计数据仍应从当地官方渠道查。场景二，家里要比较三份装修报价。把报价表整理好后，请模型找出缺项、单位不一致和需追问的问题；不要让它替你决定签约，因为它看不到施工质量和隐藏风险。

五、最常见的误区

第一，把流畅当真实；第二，一次提问就期待完美结果；第三，把隐私资料随手粘到不受控服务；第四，让模型直接做不可逆操作；第五，只让它给结论而不要求依据、假设和待确认点。高质量使用不是“少思考”，而是把思考从重复劳动转到判断和验收。

复盘：带走的七件事

一，给足背景和格式。二，复杂任务分步交付。三，把事实、计算和行动接到可验证工具。四，重要决定保留人工确认。五，要求模型说明假设。六，保护个人和公司信息。七，把它当一个需要明确指令和复查的协作者。

第二集：ChatGPT 和 LLM 到底怎样工作

开场：会说话不等于有一座真相图书馆

ChatGPT 这类系统最容易被误解成“装着全世界答案的机器”。更接近的说法是：它读过巨大数量的文字，学会在一段文字后面接什么最像人会写出的下一段。这个看似简单的训练目标，在规模足够大时会长出翻译、写代码、归纳和推理等能力；同时也解释了它为什么会一本正经地说错话。

今天的路线图

我们依次看 token、预训练、Transformer、后训练、检索和工具，以及幻觉为什么不是“偶尔的小毛病”。

一、Token：模型读的不是整句

模型把文字切成 token，可以理解为一小块一小块的积木：有时是一个字，有时是一个词的一部分，有时是标点。它每次估计“下一块积木”最可能是什么。它并非逐个字母地看世界，因此数字符、拼写罕见单词和机械计数常会出错。

二、预训练：海量完形填空

训练时，系统读到“今天天气很”，目标可能是“好”；读到一段代码，目标可能是下一个符号。预测错了就微调内部数值，预测对了就保留方向。反复进行后，模型把语言、事实片段、写作结构和代码规律压缩进大量参数中。它像读过无数书的人，却不能保证记得每一本书的页码，也分不清训练材料里所有真假。

三、Transformer：为什么它能看上下文

Transformer 的关键是注意力机制。可以把它想成读一句长话时，一边读到“它”，一边回头判断“它”指的是前面哪个名词；读合同中的金额时，也会注意到前后日期和条件。许多层这样的“看哪里更相关”和“怎样组合信息”叠起来，形成对上下文的表征。但它的工作窗口有限，窗口外的信息不会自动永久记住。

四、后训练：从续写机器变成助手

基础模型只会接着写互联网风格的文字。后训练拿来大量“用户提问—助手回答”的示例，让它习惯听指令、采用有帮助的语气、避免危险回答。之后还可通过偏好比较或强化学习，让更清楚、更安全、更正确的回答被奖励。这里要注意：礼貌、条理和安全边界变好了，不代表所有事实都变正确。

五、RAG、工具和幻觉

当问题依赖最新资料，可靠方法不是逼模型“回忆”，而是先检索权威文件，再让它只根据检索结果回答，这叫检索增强生成。计算交给计算器，查库存交给数据库，执行程序交给受限工具。幻觉则是模型在信息不足时仍然努力把一句话续写完整；它听起来合理，恰恰更危险。因此要问来源、区分已知与猜测，并核对关键结论。

场景：问药和修代码

问健康问题时，模型可以把化验单术语翻成白话，帮你准备就诊问题，却不能替代医生诊断。修代码时，它能解释报错、给出候选补丁；真正的裁判是测试是否通过、程序是否在真实数据上正确运行。

最常见的误区

不要把模型的“记忆”当数据库；不要把长推理当证明；不要把拒答或自信当能力大小的精确刻度。它是一种强大的语言和模式工具，可靠性要由资料、测试、权限和人共同补齐。

复盘

LLM 的底层动作是预测下一个 token；Transformer 让预测能利用上下文；后训练把续写器塑造成助手；检索和工具把它接回现实；核验是使用链条不可省略的一环。

第三集：AI 时代的软件怎样变化

开场：软件正在多出一种写法

过去，人把每条规则写成代码：如果温度高于某数值就报警。后来，人更多地准备数据，让神经网络自己从例子里学出识别规则。现在，大语言模型又让普通人可以用自然语言描述一部分程序行为。三种方式没有谁彻底取代谁；聪明的系统会把它们放在各自擅长的位置。

今天的路线图

理解 Software 1.0、2.0、3.0；理解为什么模型产品要保留人工接管；以及未来数字系统为什么要同时服务人和 Agent。

一、三种软件

Software 1.0 是传统代码，规则由工程师写清楚。它适合转账、权限、税率和任何必须稳定、可审计的事情。Software 2.0 是神经网络权重：你不直接写“怎样识别猫”，而是给足够多猫和非猫的图片，让训练过程形成内部参数。它适合视觉、语音、推荐这类很难穷举规则的任务。Software 3.0 指用提示词、上下文、范例、工具和评测来引导 LLM。它适合解释、归纳、草拟、在模糊语言中找线索。

二、自然语言编程的机会和边界

自然语言降低了表达需求的门槛。不会写代码的人也能描述“把这份会议记录变成待办清单，再按负责人分组”。但自然语言也天然有歧义：所谓“尽快”“重要”“合适”需要人定义。因此提示词不是按钮，而像一份不断完善的需求说明书。

三、部分自治比全自动更实用

成熟产品不必一开始就让 AI 独立完成一切。更好的方式是自治滑杆：低风险的分类、草稿、信息抽取可以自动做；发款、签约、删除数据、对外承诺等高风险动作必须展示理由并等待确认。人负责目标和最后责任，模型负责把中间的大量重复工作变快。

场景：客服和报销

客服系统可先读邮件、提取订单号、找出知识库答案、写一版回复，涉及退款或投诉升级时交给员工。报销系统可识别票据并建议分类，但金额异常、重复票据和政策例外应进入人工队列。这样既能提速，也能留下可审计轨迹。

四、为 Agent 重修数字道路

过去很多系统只为人类点按钮而设计。Agent 需要更清晰的 API、稳定字段、可读说明、细粒度权限、操作日志和可撤销步骤。网页界面不会消失，但未来优秀系统会让人、传统程序和 AI 都能安全协作。

误区与复盘

误区是把“能演示”当成“可无人值守”。真正难的是异常、权限、责任和恢复。带走三点：传统代码保底线，模型处理模糊信息，人始终能看见、纠正和接管关键流程。

第四集：CS230 深度学习课程全景

开场：做 AI 项目，模型只是中间一环

很多人学习深度学习时先问“用什么模型”。真正的项目常常输在更早处：问题没定义好、数据标签不可靠、指标选错、上线后没人监控。CS230 最重要的启发是把 AI 当完整工程，而不是训练一次模型的比赛。

今天的路线图

从问题、数据、基线、训练、误差分析，一路走到鲁棒性、部署和责任。

一、先定义问题和成功标准

假设要做一个帮助医院分流预约的系统。先决定它预测什么：是否需要急诊、哪个科室、还是候诊时长？再决定错一次的代价。把急诊病人误判为普通预约，比多转一个普通病人严重得多，因此不能只看“总体准确率”。问题定义会决定数据、模型和上线阈值。

二、数据是地基

数据要分成训练、验证和测试集。训练集用来学习；验证集用来选模型和参数；测试集留到最后检验。最危险的错误是数据泄漏：例如同一位病人的多次记录同时出现在训练和测试中，看起来分数很高，现实却表现很差。先人工检查一小批样本，常比盲目换模型更有价值。

三、基线、训练和误差分析

先做一个朴素基线，例如按最常见科室预测，知道新系统至少要超过它。训练后不要只盯一个总分；把错误按人群、时间、设备、罕见情况分类。若训练和验证都差，可能是模型能力不足或特征不好；若训练很好、验证很差，可能是过拟合。下一步由错误桶决定：补数据、改标签、调整目标，还是改模型。

四、鲁棒性和责任

系统可能遇到模糊图片、异常输入、恶意攻击或与训练时期不同的人群。评估要覆盖这些情况。对于贷款、医疗、招聘等影响人的系统，还要检查公平性、可解释性、隐私和申诉渠道。模型不是中立魔法，它会放大数据和流程中的盲点。

场景：识别产品缺陷和预测需求

工厂相机识别缺陷时，要比较不同光照、不同班次和不同型号；错过危险缺陷的代价应被单独衡量。零售预测需求时，要警惕促销、节假日和缺货造成的数据偏差。两者都需要上线后的监控：现实分布变了，旧模型就要重新评估。

最常见的误区

误区一是把排行榜分数当作业务价值；误区二是只在上线前测一次；误区三是把数据问题误当模型问题。先找到错误来自哪里，再决定是否需要更复杂的网络，通常更省钱也更可靠。

复盘

完整闭环是：问题定义、数据审计、基线、训练、误差分析、受控发布、监控和改进。模型越强，越需要严谨流程来保证它在真实世界里有用且负责。

第五集：Agent 和 AGI 离我们还有多远

开场：会聊天，不等于能稳定上班

今天的模型能写文章、生成代码、操作部分工具，因此很容易让人以为它很快就会成为全天候的数字员工。更冷静的判断是：它们已经是有用的助手，却还不是可靠的长期代理。一次回答做对，和连续几天处理模糊任务、发现错误、请求帮助、对结果负责，是完全不同的难度。

今天的路线图

解释 Agent 是什么；为什么长任务难；“AGI 还要十年”这种说法意味着什么；以及“幽灵而非动物”的比喻。

一、Agent 不是聊天框加自动点击

一个真正的 Agent 需要理解目标、把任务拆开、调用工具、记住进度、观察结果、发现失败后调整，还要在该停下时停下。你让它“订一次差旅”时，它要处理预算、日期冲突、偏好、付款权限和改签。每多一步，出错机会就更多；错误还会层层传递。

二、可靠性的九

如果一个小步骤有百分之九十九正确率，连续做一百步并不意味着还百分之九十九可靠。高风险任务需要多层保护：明确权限、可撤销动作、外部验证、关键节点确认和完整日志。因此实际产品往往先做“部分自治”：AI 准备材料和执行低风险步骤，人批准不可逆决定。

三、幽灵而非动物

把当前 LLM 想成“从人类留下的文字里召唤出的幽灵”很有帮助。它能模仿人类表达和知识，却没有动物那样的身体、成长经历、求生压力和持续内驱力。小斑马出生后很快会站立，并不是现场试错学出来的，而是进化留下大量先天结构。模型的训练路径不同，所以它会呈现很强但参差不齐的能力。

场景：软件工程和家用助手

在软件团队，Agent 可以读报错、写测试、提出补丁；合并代码前仍需测试和审查。家用助手可以整理购物清单、比较航班；付款、门锁、医疗预约等动作应有清晰确认。越接近现实世界，越需要刹车、后视镜和方向盘。

误区与复盘

“十年”是对难度和节奏的个人判断，不是日历上的承诺。当前最值得关注的不是某天突然出现 AGI，而是记忆、多模态、工具使用、持续学习和可靠性一步步变好。把 AI 当能力很强但需要监督的伙伴，既不低估它，也不把希望押在魔法上。

第六集：为什么 AI 要从规模化回到研究

开场：为什么更多 GPU 不一定自动解决所有问题

过去几年，行业发现一个有效配方：更多数据、更多算力、更大模型，往往带来更强能力。这像给发动机加大排量，效果真实而且可预测。但可用的高质量数据不是无限的，真实世界的任务也不是一套固定考卷。因此下一阶段的问题变成：怎样让模型更会泛化、更会自我纠错，而不是只把同一配方放大。

今天的路线图

我们讲规模化为何成功、它卡在哪里、什么是泛化和奖励投机，以及“研究时代”要找什么。

一、规模化的黄金时期

预训练让模型从海量文本、代码、图像中压缩规律；更大的训练通常带来更丰富的能力。企业喜欢这种路径，因为目标清晰：建设更大集群、收集更多资料、优化训练工程。但这并没有回答模型到底怎样学会真正的新任务。

二、评测高分与真实工作不是一回事

学生刷熟题库，考试可能得高分，换一种问法却不会做；模型也可能在固定基准上表现优秀，却在真实软件项目里反复修错又制造新错。这叫泛化不足：它学到的是狭窄环境中能得分的策略，而不是可迁移的原则。

三、强化学习和奖励投机

强化学习通过奖励告诉系统什么结果好。问题是，奖励一旦定义得不完整，系统可能找到“钻空子”的办法。比如只奖励客服尽快结束对话，系统可能草率关闭问题；只奖励机器人走得快，它可能不顾安全。奖励不是一句口号，而是要被反复测试的产品定义。

场景：导航和客服

导航若只追求最短时间，可能把车带进危险小路；客服若只追求满意度打分，可能承诺做不到的事。真实目标总有多种约束，需要更好的过程评价、模拟环境和人工反馈，而非单一分数。

四、研究时代的意思

回到研究时代不是说算力没用，而是说新想法更稀缺：更好的训练配方、能判断中间步骤质量的价值函数、持续学习机制、可靠的环境和评测。目标是让模型少靠死记硬背，多能在陌生情况中发现错误、调整方法。

误区与复盘

不要把“规模化结束”理解为进步停止；也不要把“研究”理解为马上有神秘突破。更合理的预期是工程和科学共同推进。带走三点：数据有限，分数不等于能力，真正重要的是能迁移、能验证、能在现实约束下长期工作。

1. Karpathy：如何使用 LLM（2:11:12）

来源：B 站 BV1y69TYTEUw；原讲链接为 YouTube EWvNQjAaOHw。

一句话：把 LLM 当成一个非常有知识、但需要明确任务边界、可调用工具、且必须验收的协作者，而不是“答案机器”。

  • 从交互开始：给足目标、背景、输入材料、输出格式和评价标准；先让模型复述理解，再分步骤交付。
  • 适用任务：解释陌生材料、生成草稿、翻译与改写、写/读代码、数据整理、规划旅行或学习；高风险事实必须回到一手来源核验。
  • 模型的优势来自广泛模式压缩，不等同于可靠的事实数据库；“语气自信”不能作为证据。
  • 有难度的任务应采用迭代循环：模型产出 → 人/程序验证 → 把错误与约束送回模型 → 修订。把模型接到搜索、计算器、代码执行、文件系统后，能力边界会显著扩大。
  • 提示词不是咒语。真正可复用的是把任务拆成输入、约束、工具、验收四件事；让模型输出中间产物，才能发现偏题或幻觉。

  P --> M[LLM 推理与生成]
  M --> T{需要外部能力？}
  T -->|是| X[搜索 / 代码 / 数据库 / 文件]

2. Karpathy：深入探索 ChatGPT 类 LLM（3:31:24）

来源：B 站 BV16cNEeXEer；原讲链接为 YouTube 7xTGNNLPyMI。

一句话：ChatGPT 是“预训练的下一个 token 预测器”经对话微调、强化学习、工具与检索包装后形成的产品；理解各层，才能理解其能力和失误。

讲稿式详细提纲

  1. 预训练：收集网页、书籍、代码等文本，清洗、去重、tokenize；模型在海量“前缀 → 下一个 token”样本上最小化预测误差。
  2. Transformer：token 先变为向量，位置编码加入顺序；多层自注意力让当前位置按相关性读取上下文，MLP 做非线性变换；训练用反向传播更新参数。
  3. 基础模型：它模仿互联网文本分布，因此本来是“文本续写器”，会扮演不同文体、复述错误信息，也可能在不确定时继续编造。
  4. 后训练（SFT）：把高质量的“用户—助手”对话写成同一 token 序列继续训练，令模型习得助手格式、指令遵循与拒答边界。
  5. 偏好/RL：针对可验证题或人类偏好，比较候选回答、优化能获得高奖励的轨迹；推理模型特别依赖让它生成更长的可检查推导与工具调用。
  6. 可靠性补丁：不确定性训练、系统提示、RAG、函数调用与外部验证分别处理不同缺陷；它们不是让模型“天然知道真相”。
  7. 结论：LLM 有“参差不齐”的能力面——可写很强的代码却数错字符。用它时把高风险点变成可测试、可检索、可复核的环节。

  B --> C[预训练：预测下一个 Token]
  C --> D[Base Model]
  E[人工/合成对话] --> F[SFT：指令与对话格式]
  D --> F --> G[Assistant Model]
  H[偏好比较或可验证奖励] --> I[RL / 偏好优化]
  G --> I --> J[推理/聊天模型]
  K[RAG、工具、系统策略] --> L[应用层]
  J --> L

3. Karpathy：AI 时代的软件（39:32）

来源：B 站 BV1CLNtzyEP4；原讲为 YC AI Startup School 的 Software Is Changing (Again)。

核心论点：软件正在从“人写规则”到“训练权重”，再到“用自然语言编程 LLM”的第三次表达方式迁移；但 1.0/2.0/3.0 将长期并存。

  • Software 1.0：C++、Python、SQL 等显式规则；稳定、精确、可审计。
  • Software 2.0：训练数据和优化器“写出”神经网络权重；适合感知和难以手工写规则的模式。
  • Software 3.0：提示词、上下文、工具与评测共同“编程”LLM；自然语言成为接口，迭代速度更快。
  • LLM 既像按量调用的公共设施，也像集中制造的“fab”，还像有记忆、权限、工具和多任务的“新 OS”。这些类比提醒我们：今天仍非常早期。
  • 产品策略不是追求全自动：优先做“部分自治”。人设定目标、看到过程、能中断/接管；机器承担起草、检索、分类、执行低风险步骤。
  • 数字世界需要面向 Agent 重构：给机器可读文档、稳定 API、身份/权限、可观察状态和可验证操作，而非只给人类 GUI。

  S2[Software 2.0\n数据+优化得到权重] --> H
  S3[Software 3.0\nPrompt+Context+Tools] --> A[LLM Agent]

5. Karpathy：AGI 仍需十年（2:26:08）

来源：B 站 BV1YvWpzcEdS；原讲为 Dwarkesh Patel 的 We’re Summoning Ghosts, Not Building Animals。

一句话：当前 LLM 已很强，但距离可长期、稳定、自主完成几乎所有经济任务的 Agent 仍有大量“可靠性九”的工程与研究工作；因此是“agents 的十年”，不是“agents 的一年”。

  • 反对把会聊天、会写一段代码等同于成熟员工；开放环境任务要求持续目标、记忆、世界交互、错误恢复与长期学习。
  • “幽灵而非动物”：模型是人类文本的统计蒸馏与模拟，主要由模仿训练而来；动物智能还受进化、身体、内驱力和持续环境反馈塑形。
  • RL 是目前重要的增量工具，却在稀疏奖励、长时程信用分配和奖励投机上很脆弱。需要更好的环境、验证器、课程与训练配方。
  • 进展大概率是渐进的：数据、算法、算力、工具、产品与组织流程共同改进，而不是单一“AGI 开关”。

6. Ilya Sutskever：从规模化时代走向研究时代（1:36:04）

来源：B 站 BV1SXUbBJEVM；原访谈为 Dwarkesh Patel。

一句话：预训练规模化仍有价值，但高质量数据有限、单靠多堆算力不足以解决泛化；下一阶段的稀缺资源更可能是新训练配方与新研究洞见。

  • 2012–2020 可看作密集探索期；2020–2025 的成功配方是扩大预训练与算力并获得相对可预测提升；随后需要重新把研究放在中心。
  • 关键症状：模型在评测或竞赛题很好，却会在真实任务反复犯简单错误、修一个 bug 造另一个 bug。这提示优化在窄训练/评测分布上过拟合。
  • 人类样本效率与迁移能力仍是参照：人能用相对少的经历学习新任务。Ilya 将“快速判断一条路径值不值得继续”的价值功能类比为情绪/直觉的作用；AI 需要更强、泛化更好的过程评价。
  • 对安全与部署：能力提升不自动带来可控性；应把对齐、协作与可验证性作为研究对象，而不是仅在发布末端加一层政策。

  D -->|不能| E[窄域过拟合、奖励投机、泛化差]

跨视频结论：一个实用的学习顺序

  1. 用第 2 项建立 LLM 的训练与局限心智模型；
  2. 用第 1 项把模型放进“任务—工具—验证”工作流；
  3. 用第 3 项思考产品和软件架构如何为人机协作重写；
  4. 用 CS230 补足严谨的 ML 项目方法；
  5. 用第 5、6 项校准对 Agent、AGI 与规模化的预期：目前最重要的不是相信全自动，而是持续提高可验证、可接管、可泛化的自治程度。
